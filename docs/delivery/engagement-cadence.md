# Engagement cadence

Use this planning view to sequence selected S0-S12 sessions. It assumes an
eight-to-twelve-week programme; customer implementation and observation may
extend the timeline without changing the evidence boundary.

| Stage | Governance delivery | Customer change and observation | Required outcome |
|---|---|---|---|
| 1. Govern | Run S0-S2: baseline, authority, and data review. | Confirm roles, records location, architecture constraints, and change route. | Baseline and owned prerequisite backlog. |
| 2. Establish | Run S3-S5: platform, engineering admission, and tool/API governance. | Review architecture, implementation paths, and controlled publication needs. | Design decisions and work list. |
| 3. Assure | Run S6-S8 when entry conditions pass. | Prepare safe targets, collect observation evidence, and execute authorised changes/testing. | Runtime, evaluation, and adversarial evidence or explicit blockers. |
| 4. Operate | Run S9-S11: reconciliation, applicability review, and operating cadence. | Close evidence gaps, validate remediation, and assign exceptions. | Control-plane, lifecycle, and operating-review records. |
| 5. Improve | Run S12 with the sponsor and governance lead. | Accept portfolio priorities and next-cycle work. | Portfolio decision and next S0 roadmap. |

## Facilitator rhythm

Hold a short working review each week. Review passed/blocked gates, evidence
quality, customer-owned changes, observation periods, exceptions, and decisions
requiring sponsor escalation. Keep technical working sessions separate from
approval meetings.

## When the plan changes

Move an unready session rather than improvising around a missing role, license,
platform record, architecture decision, or safe target. Update the selected
sequence, dependency, owner, and target date in the customer register. Preserve
S0 as the entry point and S12 as the portfolio close for the current cycle.
