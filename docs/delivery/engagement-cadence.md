# Engagement cadence

Use this planning view to sequence selected S0-S12 sessions. It assumes an eight-to-twelve-week programme; customer implementation and observation may extend it without changing the evidence boundary.

| Stage | Governance delivery | Customer change and observation | Required outcome |
|---|---|---|---|
| 1. Govern | Run S0-S2: baseline, authority, and data review. | Confirm roles, records location, architecture constraints, and change route. | Baseline and owned prerequisite backlog. |
| 2. Establish | Run S3-S5: platform, engineering admission, and tool/API governance. | Review architecture, implementation paths, and controlled publication needs. | Design decisions and work list. |
| 3. Assure | Run S6-S8 when entry conditions pass. | Prepare safe targets, collect observation evidence, and execute authorised changes/testing. | Runtime, evaluation, and adversarial evidence or explicit blockers. |
| 4. Operate | Run S9-S11: reconciliation, applicability review, operating cadence, and LLM operations where applicable. | Close evidence gaps, validate remediation, assign exceptions, and route model/prompt lifecycle work. | Control-plane, lifecycle, operating-review, and LLM-operations records. |
| 5. Improve | Run S12 with the sponsor and governance lead. | Accept portfolio priorities and next-cycle work. | Portfolio decision and next S0 roadmap. |

## Facilitator rhythm

Hold a short weekly review of gates, evidence quality, customer-owned changes, observation periods, exceptions, and sponsor escalations. Keep technical working sessions separate from approval meetings.

## When the plan changes

Move an unready session rather than improvising around a missing role, license, platform record, architecture decision, or safe target. Update its sequence, dependency, owner, and target date in the customer register. Preserve S0 as entry and S12 as the current-cycle portfolio close.
